# نظام الكافيه

تطبيق Flutter محلي لويندوز لإدارة الترابيزات وأوضتي بلايستيشن والطلبات والمبيعات.

## تشغيل المشروع

```powershell
cd D:\cafe_system
flutter pub get
flutter run -d windows
```

يعتمد المشروع على `sqflite_common_ffi` لتشغيل SQLite على ويندوز. ينشئ التطبيق قاعدة البيانات تلقائيًا عند أول تشغيل. وتشمل البيانات أصناف المنيو، الترابيزات، أوض البلايستيشن، الطلبات، وصفات الأصناف، مخزون المكونات، استهلاك كل فاتورة، مكونات كل صنف المحذوفة، والإعدادات.

```text
%LOCALAPPDATA%\CafeSystem\cafe_system.db
```

يرفع التطبيق إصدار قاعدة البيانات تلقائيًا عند إضافة مخطط جديد ويحافظ على الطلبات والمبيعات الحالية. إذا وجد ملف البيانات القديم `cafe_data.json` في مجلد `CafeSystem`، يحاول استيراده مرة واحدة ثم ينقله إلى `cafe_data.json.migrated.bak` للاحتفاظ بنسخة احتياطية.

## إدارة المكونات

من تبويب **المكونات** تقدر تضيف مكوّن ووحدة قياس ورصيد، وتزوّد الكمية عند التوريد، وتحدد مقدار كل مكوّن في كوب أو قطعة واحدة من كل صنف. عند تحصيل الفاتورة يُخصم الاستهلاك من المخزون، مع تجاهل أي مكوّن طلبه الزبون «بدون». يسجل التطبيق استهلاك الفاتورة وقت البيع حتى تظل التقارير القديمة صحيحة بعد تعديل الوصفة. المقادير والأرصدة الافتراضية أمثلة أولية؛ راجعها واضبطها على وصفات ومخزون الكافيه الفعلي.

## إدارة المنيو وإغلاق اليومية والنسخ الاحتياطي

- من تبويب **المنيو** يمكن إضافة صنف، وتعديل قسمه وسعره ومكوناته القابلة للإزالة، أو إخفاؤه. اسم الصنف الحالي ثابت حتى تظل الفواتير والوصفات السابقة مرتبطة به. وصفة المخزون تُعدّل من تبويب المكونات.
- من تبويب **التقارير** يمكن إغلاق يومية اليوم مرة واحدة. يحفظ النظام إجمالي المبيعات وعدد الفواتير، ويمنع تحصيل فواتير جديدة في اليوم بعد الإغلاق.
- من تبويب **النسخ الاحتياطي** يمكن إنشاء نسخة SQLite كاملة أو استعادة نسخة سابقة. تُحفظ النسخ في `%LOCALAPPDATA%\CafeSystem\Backups`. قبل الاستعادة ينشئ التطبيق نسخة من البيانات الحالية ويفحص سلامة النسخة المختارة.

## تنظيم الكود

- `lib/core`: ثوابت وإعدادات مشتركة لا تعتمد على الشاشات.
- `lib/data/database`: فتح SQLite وإنشاء المخطط وترقيته.
- `lib/data/models`: نماذج البيانات. `cafe_order_item.dart` يمثل سطر الطلب، و`cafe_order.dart` يمثل الطلب كاملًا، و`cafe_snapshot.dart` يمثل البيانات المحمّلة للواجهة.
- `lib/data/models/default_cafe_products.dart`: كتالوج البداية منفصل عن تعريف `CafeProduct`؛ تعديلات المنيو المحفوظة تُقرأ من SQLite.
- `lib/data/repositories`: مصدر البيانات وعمليات القراءة والكتابة.
- `lib/ui/screens`: تركيب الشاشة وتخطيطها.
- `lib/ui/widgets`: مكونات الواجهة. اجعل كل مكون قابل لإعادة الاستخدام إذا كان له استعمال واضح، واجمع العناصر الخاصة المتداخلة التي لا معنى لها خارج مكونها.

إرشادات Flutter الرسمية تفصل الواجهة (View وViewModel) عن البيانات (Repository وService)، وتوصي بإنشاء طبقة منطق إضافية فقط عند وجود منطق معقد أو متكرر. لا تفرض قاعدة class واحدة في كل ملف؛ الفاصل المفيد هو المسؤولية والترابط، مثل إبقاء `State` الخاص بـ`StatefulWidget` معه.
